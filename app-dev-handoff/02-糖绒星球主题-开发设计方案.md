## 1. 整体开发思路与设计目标

### 1.1 开发思路

按「设计系统 → 组件架构 → 视觉层级 → 验证」推进，而不是逐条打补丁：

1. 先定**设计 token**（糖果色、深棕手绘描边、8px 间距节奏、阴影与动效分层），再定 1440×940 基准画布与三列 52px 呼吸带。
2. 每个功能区做成**形态不同**的物件（玻璃展柜 / 麻绳拍立得 / 手账便签 / 开放层板 / 黑胶唱片机），避免变成规整仪表盘。
3. 用户反馈先归并成同一个空间 / 结构问题再一次性重排：v3 把「展柜太大 / 电脑太大 / 垃圾桶太大 / 右下空 / 太紧凑」归因为**列间距只有 16–18px**，主刀是拉开呼吸带 + 缩小三件物件 + 摊开右下。
4. 每轮闭环：改 HTML → `node --check` 抽出的内嵌 JS → Electron + CDP 真交互验证 → 截图肉眼核对 → 同步说明与日志。

### 1.2 设计目标

- 打开即看、打开即玩：单文件、零依赖、无构建步骤、无网络请求。
- 「女生向潮玩怪萌」但不甜腻：糖果色打底 + 深棕手绘描边压住，粉色只留给主操作与高亮。
- 五个功能**全部收进同一个场景**，不做多页面、不做侧边导航。
- 交互门槛低：把生产分支的 `Alt 框选` 换成**点选模式**（点一下选中、批量上架），鼠标与触屏都自解释。
- 动效有分工：常驻只做呼吸 / 钟摆 / 星尘；Q 弹、飞行吸附、撒星、显影只出现在操作反馈里。
- 可访问性进基础：焦点环、`aria-label`、键盘上传、`prefers-reduced-motion` 降级。

### 1.3 明确不做的事（判据口径）

- **只有** `docs/theme-preview.html` 算本主题线的实现，其余一律不算；生产分支 `room/` 不在本分支改动范围内。
- **只有** `PNG` / `GIF` 且单张 ≤ 5MB 的文件算可放入展柜的形象，其余一律拒绝。这是浏览器解码与存储配额的**代码限制**，不是支持格式清单。
- 展柜**只有** 1–6 只站位（代码限制，必须显式标注），不是业务上的系列数量清单。
- **不内置、不生成、不复制任何外部角色素材**；系列名只是展柜主题标签（格数 / 配色 / 灯带 / 铭牌），不是外部形象库。
- 相册自动轮换、一框多图、网络图片、歌词波形、系统媒体键、多页路由：不做。
- 不读写真实文件系统：图片走 `FileReader`，MP3 走 `ObjectURL`，都在本页内存里。

## 2. 技术架构与关键选型

### 2.1 运行形态

单文件 HTML：所有 CSS、JS、SVG 插画**内联**，零外部依赖。`#app` 固定 **1440×940** 基准画布，`fit()` 按 `min(vw/1440, vh/940)` 等比缩放并居中。所有内部坐标基于基准画布，拖拽位移在应用前除以 `SCALE`。

Electron **不是运行依赖**，只在验证时作为 CDP 宿主（`verify/preview-host.js`）。浏览器直接双击打开即可。

> 关键约束：入场动画只能动 `opacity` / `filter`，**不能写 `transform`**，否则会覆盖 `fit()` 的缩放（v2 实测踩过：DOM scale 被改成 1）。

### 2.2 技术栈与选型理由

| 选型 | 形态 | 理由 |
|---|---|---|
| 单文件 HTML | 内联 CSS / JS / SVG | 交接、预览、分发都只要一个文件；无构建、无包管理 |
| 原生 DOM + CSS 变量 | `:root` token + `body.night` 等 | 主题切换只改变量；不引入框架 |
| 内联 SVG | `sprite()` 生成器 + 图库 | 原创角色与图标全部矢量，无外部图片、无许可风险 |
| CSS 立体舞台 | 绝对定位 + 站位阵列 + 阴影 / 滤镜 | 比真 3D 可控、性能好，且能表达前后高低错位 |
| Web Audio | `OscillatorNode` + `GainNode` | 没选本地 MP3 时现场合成演示旋律，点播放真的能出声 |
| `<audio>` + `ObjectURL` | 用户选本地 MP3 后 | 真实文件播放，三态模式对真实 `ended` 生效 |
| `localStorage` | `fluffy.showcase.v3` | 展柜配置刷新后仍在；超配额降级为会话内有效并提示 |
| `FileReader` → dataURL | PNG / GIF 上传 | GIF **不转码**，动效原样保留；`object-fit:contain` 不裁切 |
| Electron + CDP | 仅验证 | 驱动真实浏览器注入断言与截图，不打桩 |

### 2.3 目录结构与文件职责

| 路径 | 职责 |
|---|---|
| `docs/theme-preview.html` | **唯一实现**：结构、样式、逻辑、SVG、说明抽屉全在此 |
| `docs/theme-preview.png` | 1600×1000 视觉证据，由验证脚本生成 |
| `docs/theme-check.json` | 27 项断言结果（含 `pageErrors`） |
| `verify/verify-theme-preview.mjs` | 端到端验证：启动 Electron、CDP 断言、生成真 PNG/GIF 测试素材、截图 |
| `verify/preview-host.js` | 验证宿主，用 Electron 加载概念稿 HTML |
| `verify/logs/` | 验证时生成的临时测试图片落点 |
| `docs/发音盒播放器方案.md` | 生产分支方案（已实施），**不属于本主题线** |
| `docs/相框群交互调整方案.md` | 生产分支方案（已实施），**不属于本主题线** |
| `app-dev-handoff/` | 本目录：两条主题线的交接文档 |

> `verify/verify-theme-preview.mjs` 与 `preview-host.js` 已从工作区临时目录固化到项目内，路径全部用 `import.meta.dirname` / `__dirname` 相对推导，不含任何绝对路径。

### 2.4 数据流与持久化

| 数据 | 位置 | 生命周期 |
|---|---|---|
| 展柜配置 `sc = {series, count, imgs[6], names[6]}` | `localStorage['fluffy.showcase.v3']` | 刷新保留；超配额降级为本次会话 |
| 系列主题（格数 / 配色 / 灯带 / 铭牌） | 内存常量 `SERIES` | 静态 |
| 站位阵列 `STAGES[1..6]` | 内存常量 | 静态 |
| 相册 4 格、待办 6 条、书架 5 层、8 张散乱资料、播放列表 | 内存数组 | 刷新即重置为演示预置 |
| 上传的 PNG / GIF | dataURL 存在 `sc.imgs` | 跟随 localStorage |
| 本地 MP3 | `URL.createObjectURL` | 本次会话 |

约定：**切系列只换主题与站位，`sc.imgs` 数组不缩短**，所以已上传的图永不丢失；增减站位同样只改 `sc.count`。低频配置单独存，不与演示状态混在一起。

### 2.5 安全边界与隔离

- 上传只接受 `image/png` / `image/gif`（或同名扩展），≤ 5MB，用 `new Image()` 预解码，读不出来就提示并拒绝写入。
- 图片一律 `object-fit: contain`，不裁切、不转码；GIF 动效原样保留。
- 展位 `data-i` 只作为数组下标，不接受任意路径或命令。
- 所有用户可见文本走 `esc()` 转义；`localStorage` 读取包 `try/catch`。
- 浏览器原型**不接触真实文件系统、不发起网络请求**；验证脚本生成的测试图落在 `verify/logs/`。

## 4. 各模块的特色与作用

> 每模块固定四栏：职责 / 特色 / 关键实现 / 可证伪判据。判据是回归时必须守住的线。

### 4.1 M1 设计 token 与基准画布

- **职责**：统一配色、缩放、昼夜与动效降级。
- **特色**：糖果色打底 + 深棕手绘描边；`fit()` 等比缩放；入场动画只动 `opacity/filter`，`transform` 永远留给缩放。
- **关键实现**：`:root` CSS 变量；`prefers-reduced-motion` 媒体查询一刀切关掉动画。
- **判据**：DOM `scale` ≈ `1.06383`（1600×1000 视口）；页面零报错。

### 4.2 M2 三列布局系统

- **职责**：给所有区块定坐标，解决「局部挤、右下空」。
- **特色**：**52px 呼吸带**（v2 只有 16–18px），垂直区块间距 20px；所有区块底部收在柜体 820 高度内不裁切。
- **关键实现**：左列 `x48 w352`、中列 `x452 w478`、右列 `x982 w358`；展柜 `478×420`、书架 `358×470`、唱片机 `358×168`。
- **判据**：实测 gutter `49 / 52px`；无元素越出柜体边界。

### 4.3 M3 立体玻璃展柜

- **职责**：让玩偶「真的站在柜里」，不是并排卡片。
- **特色**：连续玻璃空间——背板径向纵深、`clip-path` 锥形射灯、椭圆地台带前沿厚度、每只玩偶脚下接触阴影 + 小圆展台；编号与名牌收进 hover。
- **关键实现**：`.figure` 绝对定位，`translate(-50%,-100%) scale(var(--s)) rotate(var(--rot))`，用 `z-index` + `brightness` + `blur` 造景深。
- **判据**：5 只玩偶的 `--s` 与 `--z` 各至少 4 个不同值；`figure__shadow` / `figure__stand` / `stage__floor` / `stage__lamp` 齐全；截图里 5 只全部可见且高低错落。

### 4.4 M4 系列主题与站位阵列

- **职责**：系列切换与站位排布。
- **特色**：`37cm 大号 / 焦糖 / 星星人 / 自定义` 切的是**主题**（格数、配色、灯带、铭牌），不是外部形象库；远排靠上 / 小 / 淡 / 模糊 / 低层级，近排靠下 / 大 / 亮 / 高层级。
- **关键实现**：`STAGES[1..6]` 站位表 `S(x,y,s,z,rot,b,blur,w,h)`；`sc.imgs` 定长 6，切主题不缩短。
- **判据**：切焦糖 → 3 只且已上传图保留；切大号 → 1 只大玩偶且图仍保留；`+ / −` 在 1–6 之间生效。

### 4.5 M5 展柜自定义

- **职责**：数量、形象、位置全部可自定义。
- **特色**：三条换位入口（拖拽 / ‹ › / 右键）；GIF **不转码**保留动效；右键可替换 / 移除 / 交换。
- **关键实现**：`DOM.setFileInputFiles` 可验证的完整上传链路；`FileReader` + `new Image()` 预解码；`localStorage` 持久化，超配额降级提示。
- **判据**：真 PNG 上传后 `sc.imgs[0]` 是 `data:image/...` 且出现真 `<img>`；GIF 前缀为 `data:image/gif`；‹ › **恰好交换一次**（不重复绑定）；真实拖拽 `0↔3` 生效。

### 4.6 M6 我的电脑

- **职责**：左上入口与配套物件。
- **特色**：**140×140 正方形**深蓝玻璃屏，屏内显示磁盘 C: 与内存占用率（进度条 + 百分比，浅字亮条满足 WCAG AA）；机箱与屏幕等高；多肉放大到 78×88。
- **关键实现**：`renderPCStats()` 原型用模拟值 + 每 12 秒轻微波动；整机可点弹 6 个快捷入口，双击切屏保；正式版入口接 `shell.openPath`。
- **判据**：屏宽 === 屏高；机箱高 === 屏高 140；植物 ≥ 70px；快捷入口 6 项；双击屏保时状态信息 `display:none`。

### 4.7 M7 甜甜相册

- **职责**：玩家自定义相框内容。

- **特色**：模式按钮固定短标签「**模式**」，当前状态放副标题「MP3 · 列表循环」与 tooltip，三个按钮强制一排；卡片高度 168px，与下方糖果罐留 34px 间隙。

## 6. 已知问题或风险

### 6.1 技术风险

| 风险 | 表现 | 缓解 |
|---|---|---|
| `transform` 覆盖缩放 | 入场动画若写 `transform:scale(1)`，会覆盖 `fit()` 的等比缩放 | 入场只动 `opacity/filter`；验证里断言 DOM scale |
| 合成 PointerEvent 伪异常 | `setPointerCapture` 在合成事件上抛 `Uncaught` | 验证一律用 CDP `Input.dispatchMouseEvent` 真实鼠标事件 |
| `$$(sel, root)` 第二参数被忽略 | 会导致每个展位的 ‹ › 按钮被重复绑定，点一次交换多次 | 用 `Array.from(root.querySelectorAll(sel))`；验证断言「恰好交换一次」 |
| 站位遮挡 | 前排大玩偶完全盖住后排，等于「放了看不见」 | 拉开 y 跨度、错开 x；截图核对每只都露出 |
| 曲名行省略号 | 把模式名放曲名行会被截断 | 状态改放副标题与 tooltip |

### 6.2 数据与文件安全风险

- `localStorage` 约 5MB 配额，dataURL 图片容易超限；已做 try/catch 降级为会话内有效并提示，但**不做自动压缩**（会破坏 GIF 动效）。
- 原型**不接触真实文件系统**，因此不会移动、删除用户文件；这也是它不能直接当产品用的原因。
- 验证脚本生成的测试图片落在 `verify/logs/`，不落在用户桌面。

### 6.3 素材与合规

- 界面与内置形象均为本项目矢量绘制；外部图片由使用者自行上传。
- 对外分发时，请确认所使用素材的授权。

### 6.4 平台与环境风险

- 固定基准画布在极端宽高比或小屏上会留白；尚未做响应式断点。
- Web Audio 演示旋律需用户点击后才能创建 `AudioContext`（浏览器自动播放策略），这是设计内行为。
- `localStorage` 在 `file://` 协议下不同浏览器策略可能不同；验证用的是 Electron `loadFile`。

## 7. 开发者的编码风格与偏好约定

> 本章与主题无关，两条主题线**完全共用**。接手后按本章写规则、写代码、写文档。

### 7.1 判定规则的写法（铁律）

| 要求 | 正确写法 | 禁止写法 |
|---|---|---|
| 口径 | 「**只有 X 算，其余一律不算**」 | 「A 不收 / B 不收 / C 不收」 |
| 清单 | 给**判据**（「子目录怎么分都行，代码不看目录名」） | 把可选项写死成枚举（「子目录是 A/B/C」「题型只有甲乙丙」） |
| 层次 | 从**身份 / 位置**说（「有 `Page/知识卡片` 标签就是卡片，与目录无关」） | 从「排除了哪些」说 |
| 例外 | 只有真正写死在代码里的约束才可枚举，且**必须注明「这是代码限制」**（如展柜 1–6 格） | 把业务可选项伪装成代码限制 |

理由：穷举永远列不全，新增一个就漏一个；列出来的反面还会暗示「没列到的可以」。不能以后多一个再改一次代码。适用面：Agent 文档、代码注释、提示词、任何规范条目。历史教训可留作注脚，但**不写进规则本身**。

### 7.2 代码与工程约定

- 纯逻辑抽成独立可单测模块，不把判据埋在 Electron handler 里（`store.js`、`player-state.js` 就是这个模式）。
- 一份逻辑要被主进程与渲染进程共用时写成 UMD，`player-state.js` 是范例。
- IPC 一律白名单：`preload.js` 只做转发，不新增任意路径 / 任意命令的透传。
- 低频配置单独存文件，不混进高频写的 `layout.json`；写盘用临时文件 + `rename` 原子替换。
- 配色、类型识别用「查表 + 默认色 / 默认分支」，不是「支持类型清单」，新格式不改代码也能显示。
- 零新增依赖优先。确需引入第三方包，先给体积、许可、最近维护状态的真实证据再决定。
- 复杂脚本写到文件再执行，不在 shell 里拼中文、正则和转义。
- 命名与注释用中文说明「为什么」，代码标识符用英文。

### 7.3 验证约定

- **沙箱隔离**：用 `XOME_TEST_DESKTOP` / `XOME_TEST_DATA` / `XOME_TEST_NO_PIN` / `ROOM_SELFTEST` 把主进程指向临时目录；绝不在真实桌面、真实 `%APPDATA%\xome-room` 上跑会移动文件的测试。
- **真链路**：CDP 驱动真实 Electron 注入断言，不是打桩；断言里会真的把临时文件收进书架再逐条还原。
- **可证伪**：判据是数字或状态（`桌面 11→8 / 书架 0→3`、`8→7`），不是「看起来正常」。
- **同步断言**：行为变化必须同步改断言数字，不更新断言等于放过真实变化。
- **零报错**：页面 `pageErrors: []` 是硬指标；结果文件的 `extra` 字段必须脱敏。
- **全量回归**：改动后跑全部回归，不只跑新增部分。
- **边界写明**：真实音频解码、系统原生对话框、极端素材等自动化没覆盖的，写进「已实施但未验证」，不写进结论。

### 7.4 文档与同步约定

- 方案文档改为「已实施」时追加实施记录，**原始方案文本保留**，便于对照。
- 代码改动同步 `release/桌面房间/resources/app/room/` 与 `build/stage/room/`，逐字节 `cmp` 校验；`tools/使用说明.txt` 同步到 `release/桌面房间/使用说明.txt`。
- README、方案文档、工作区日志（`.workbuddy/memory/YYYY-MM-DD.md`，**追加不覆盖**）同步更新。
- 结论分「已验证 / 未验证」两栏，未验证的不写进结论；数字以实际运行结果为准。
- 结案的需求写「已结案、不再做」，不要继续挂在「下一步」里。

### 7.5 脱敏与发布约定

- 公司名、人名、密码、账号、内网地址、凭据、token、用户名目录、绝对路径：**一律不进入**代码、测试桩、断言、日志，以及任何对外分享的文件。
- 导出 / 分享任何内容前**必须先脱敏扫描**（宽模式正则，不只扫几个关键词），打包后再验一遍压缩包内容与路径。
- 交付时说明「改了什么、保留了什么」。
- 可保留（已确认）：公开机构 / 媒体名（方法论示例）、文档格式扩展名、功能性必需的公开域名。
- 判据：**能不能反推到「我方」或「我个人」**。能 → 删 / 泛化；只是公共知识或技术必需 → 留。
- 自有项目内容改完**默认直接发布上线**，不逐次询问；只有两类才问：① 会覆盖别人正在用的东西；② 发布失败需要人处理。

### 7.6 UI 协作术语约定

- 说「**表格**」= 带表头、分列对齐的标准表格，不是卡片、不是行卡。
- 说「**列表**」时**先要参照物再动手**：可能指表格，也可能指连续行列表。
- 界面需求偏「结果形态」（要长成什么样），不说组件名 ⇒ **参照物优先于文字**。
- 用户给非专业吐槽时，不要逐条打补丁：先把多条反馈归并成同一个空间 / 结构问题，再一次性重排。
- 设计决策由项目负责人定夺；只给一个方案，不给多选项让人挑。

| 站位阵列 | 概念稿中展柜玩偶的绝对定位参数组（位置 / 缩放 / 层级 / 明暗 / 景深） |
| 呼吸带 | 相邻列之间的固定留白，用来解决「局部挤、局部空」 |
| 命中穿透 | 桌面层空白处把鼠标事件交还给真实桌面，命中区才接管 |
| 结案 | 明确决定不再做的需求，从待办中移除但保留决策记录 |
| 代码限制 | 真正写死在代码里的约束（如展柜 1–6 格），必须显式标注，不算业务枚举 |
