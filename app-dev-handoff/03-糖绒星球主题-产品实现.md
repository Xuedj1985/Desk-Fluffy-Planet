## 0. 文档定位与阅读顺序

### 0.1 这条主题线是什么

**糖绒星球**是项目的第二个桌面主题 App：一整个粉色磨砂玻璃收藏盒，铺满桌面工作区、位于所有应用之下；最底层是概念稿的三色渐变，柜体外面不再透出壁纸。左列「我的电脑 → 甜甜相册 → 今日小愿望」、中列「立体玻璃展柜 → 地毯上的散乱资料」、右列「五层糖果书架 → 糖霜唱片机」，右下角是糖果罐。

它与「桌面房间」共用同一套底层语义：**桌面文件真移动、可还原、写日志**；相册存快照；唱片机三态；窗口不抢焦点、空白处点击穿透。差别在形态：桌面房间是一间手绘插画房间，糖绒星球是一个潮玩收藏柜。

状态：**已实装**，入口 `release/糖绒星球/糖绒星球.exe`（约 285MB 文件夹版，双击即用、不安装、不需要管理员权限）；桌面快捷方式 `糖绒星球.lnk` 指向该 exe，图标用 exe 内嵌的星球徽章，`npm run shortcut` 可重建；开发态 `启动糖绒星球.bat` 或 `npm run planet`。

## 1. 整体开发思路与设计目标

### 1.1 开发思路

按「先复用底层语义 → 再搭视觉骨架 → 逐个功能区产品化 → 最后用真交互验证」推进：

1. **不重写收纳引擎**。桌面文件真移动、撞名不覆盖、还原、批量、对账、日志这一整套已经在 `room/store.js` 里被 42 条单测覆盖。第二个主题若复制一份，两边行为迟早分叉。因此 `planet/main.js` 直接 `require('../room/store')`，`planet/index.html` 直接加载 `../room/player-state.js`。主题只是外观，语义只有一份。
2. **视觉按设计稿的坐标系统重建**。基准画布 1440×940，柜体 1388×820，三列 52px 呼吸带。展柜、相册、书架、唱片机的尺寸与站位直接取自概念稿，保证「看起来是同一个东西」。
3. **每个功能区都落到真实能力**。概念稿是内存状态 + `localStorage`；产品版把展柜形象存成文件、相册存快照、便签存 `layout.json`、音乐走本地 MP3、电脑读数接系统 API，避免「演示好看、一用就假」。
4. **每轮闭环**：改代码 → `node --check` → 纯逻辑单测 → Electron + CDP 真交互验证 → 截图肉眼核对 → 同步文档与打包版。不以「看起来正常」收尾。

### 1.2 设计目标

- 打开即看、打开即玩：不需要先配置，首屏就有 5 只原创占位玩偶、5 张示例便签、满地毯的真实文件。
- 桌面是桌面的一部分：不抢焦点、空白处点击穿透；被应用窗口盖住是正常的。
- 文件操作可追溯、可撤销：每次移动写 `journal.jsonl`，可一键还原全部；便签撕掉可撤销，丢进糖果罐会归档成文本。
- 视觉不甜腻：糖果色打底，深棕描边压住，粉色只给主操作与高亮。
- 展柜是玩家的，不是陈列模板：玩偶可以在玻璃柜里自由拖动摆放，系列名可以改，摆乱了能一键重排。
- 适配可用：1920×1080 到 3120×2080 都能完整显示；托盘右键可切「画面适配」档位；底部永远给 Windows 任务栏留安全间距。
- 判据可证伪：断言是数字或状态，不是主观描述。
- 书架先要能认人：书脊至少完整写出前四个字；快捷方式不能只剩一个数字，要和资料用同一种竖排书名语言。

### 1.3 明确不做的事（判据口径）

- **只有**桌面上的文件、以及书架里已收纳的原件算可操作文件，其余路径一律拒绝（`insideKnown`）。
- **只有** PNG / GIF 且单张 ≤ 5MB 算可放进柜的形象，其余一律拒绝。这是解码与存储的**代码限制**，不是「支持格式」清单。
- **只有** 1–6 个展位、4 格相册、5 层书架算合法容量，其余一律夹取或拒绝。这是写死在布局与实现里的**代码限制**，不是业务枚举。
- **只有** 5%–95% 横向、18%–98% 纵向算合法的自由摆位范围，拖出玻璃柜一律夹回。这是展柜几何的代码限制。
- **只有** `auto / fhd / qhd / wqhd / uhd` 五个画面档位算可选参考分辨率，其余一律回落到自动。这是托盘菜单的代码分支，不是机型清单。
- **不内置、不生成、不复制任何外部角色素材**；系列名只是展柜主题标签（格数 / 配色 / 灯光 / 铭牌），内置形象一律是原创「糖绒小精灵」。
- 任务栏条集成**已结案**（与 01 同一决策）：使用者自己把快捷方式固定到系统任务栏。
- 相册自动轮换、一框多图、网络图片、歌词波形、系统媒体键、多页路由：不做。
- 副屏覆盖、休眠唤醒、虚拟桌面切换：未做，见 §5。

## 2. 技术架构与关键选型

### 2.1 运行形态

`planet/main.js` 创建一个 `focusable:false`、`type:'toolbar'`、`transparent:true`、`frame:false` 的 BrowserWindow，铺满主屏 `workArea`（不含任务栏）。`win.setIgnoreMouseEvents(true, { forward: true })` 让空白处事件穿透；渲染进程按鼠标位置命中区动态切换。窗口层级由 `room/win32.js` 钉在 `Progman` 之上并 800ms 重锚。

因为 `focusable:false` 收不到键盘事件，修饰键一律读鼠标事件自带的 `altKey`；只有弹便签编辑器时才临时 `setFocusable(true)`。

**分辨率适配与底部安全间距**（第二轮加）：

- `fit()` 用 `document.documentElement.clientWidth/clientHeight` 取真实布局视口，按 `24–56px`（窗口高度的 3%，夹取）预留底部安全间距，再在剩余高度里等比缩放居中。窗口本身铺在 `workArea`（不含任务栏），安全间距是第二道保险，自动隐藏任务栏弹出来也压不住糖果罐和提示条。
- **画布横向展开**：`stageWidth()` 按窗口宽高比算画布宽度，夹在 `1440–1720`。16:9 时 940 高的画布展开到 1671，中间展柜从 478 变到 709，柜体几乎铺满宽度；3:2（3120×2080）与竖屏保持 1440 基准。`#app` 宽度、`--stage-w`、`--mid-w` 由 `fit()` 实时写入，CSS 里柜体、顶栏、展中/地毯、右列都跟着变量走。
- 画面档位 `auto / fhd(1920×1080) / qhd(2560×1440) / wqhd(2880×1620) / uhd(3120×2080)` 存在 `display.json`。`fitFor()` 先用参考分辨率（也按它的宽高比展开画布）算目标缩放，再用当前窗口夹取——档位只决定 UI 大小，永远不会把画面撑出窗口。
- 档位入口在**托盘右键 →「画面适配」**（radio 菜单，重建菜单刷新勾选）；渲染进程收到 `planet:display` 后立即重算。没有托盘时也能通过 `planet:display-set` 切换（验证走这条）。

**缩放**：`planet.js` 用 `document.documentElement.clientWidth/clientHeight`（不是 `window.inner*`）算 `min(vw/1440, vh/940)`，居中偏移后 `transform: translate(ox,oy) scale(s)`。同时监听 `resize`、`visualViewport.resize`、`ResizeObserver(documentElement)` 与主进程的屏幕变化事件——这是本次实测出来的缺陷：页面缩放时 `innerHeight` 会比真实布局视口大 2%，柜体会上下溢出。

### 2.2 技术栈与选型理由

| 选型 | 形态 | 理由 |
|---|---|---|
| Electron `^38.8.6` | 既有依赖 | `dialog` / `nativeImage` / `protocol` / `shell` / `Tray` 全套本地能力，零新增库 |
| `room/store.js` | 直接 require | 收纳语义只有一份；42 条单测继续有效 |
| `room/player-state.js` | 直接加载（UMD） | 三态状态机只有一份；渲染进程与服务端单测共用 |
| `room/win32.js` | 直接 require | koffi 钉桌面层，spike 已验证 |
| 原生 DOM + CSS 变量 | 渲染进程 | 单层场景不需要框架；主题色、系列色全走 CSS 变量 |
| 内联 SVG | `sprite()` 生成器 | 原创角色与图标全部矢量，无外部图片、无许可风险 |
| 展柜形象 = 文件 + JSON | `figures/sN.png` + `showcase.json` | `localStorage` 只有约 5MB，一张 GIF 就爆；文件方案没有配额、GIF 不转码、不把二进制塞进 JSON |
| 相册 = 快照 | `nativeImage` → JPEG / 原字节 | 书架收纳会真移走文件，引用原路径会让相册「一上架就碎」 |
| 真实系统读数 | `fs.statfsSync` + `os` | 概念稿的 68% / 42% 是假数字，产品版必须真；取不到就显示「—」而不是编一个 |
| 演示旋律 | Web Audio `OscillatorNode` | 没选 MP3 时点播放也能出声，避免「按钮没反应」；只在用户点击后创建 `AudioContext` |
| 验证 | CDP over WebSocket | 驱动真实 Electron 注入断言，不打桩 |

### 2.4 数据流与持久化

配置根 `%APPDATA%\xome-planet\`（验证时 `XOME_TEST_DATA` 指向临时目录）：

| 文件 | 内容 | 写入频率 |
|---|---|---|
| `layout.json` | 便签数组、地毯落点（按文件名） | 高（拖拽落点即写，320ms 去抖） |
| `shelf.json` | 书架条目（原路径、收纳路径、层号、`order`、子项数） | 中 |
| `journal.jsonl` | 每次移动一行（intent / done 成对，另有 discard） | 中 |
| `shelf\` | **被收纳的原件，不要删** | 中 |
| `frames.json` + `frames\` | 相册每格对应的快照（按格 id `p1..p4`） | 低 |
| `showcase.json` + `figures\` | 展柜系列、站位数、每格形象文件名与名字、自由摆位 `poses`、系列自定义名 `labels` | 低 |
| `audio.json` | 唱片机目录、模式、索引、音量 | 低 |
| `display.json` | 画面适配档位（`auto / fhd / qhd / wqhd / uhd`） | 极低 |
| `notes-archive.md` | 从糖果罐归档的便签文本（只追加） | 低 |
| `app.pid` | 当前进程 pid，供 `退出糖绒星球.bat` 精确杀进程 | 启动 / 退出 |

约定：**低频配置单独存文件**，不混进高频写的 `layout.json`；所有 JSON 写盘走「临时文件 + `rename`」原子替换。展柜与相册存的是**文件名**，不是绝对路径；读取时再拼 `DATA_DIR` 并用 `pathToFileURL` 编码。

### 2.5 安全边界与隔离

- `preload.js` 只暴露明确列举的 46 个方法 / 属性 / 事件订阅，**不接受任意路径或任意命令透传**。
- 文件操作只认桌面与收纳目录两处（`insideKnown`）；改名只认桌面。
- `xome-planet-audio` 在 `app.whenReady()` 之前注册且只注册一次，`privileges` 含 `stream:true`；协议层再校验「已选目录内的 `.mp3`」，压平 `../` 后判前缀。
- `dialog.showOpenDialog` 不传 parent（窗口 `focusable:false`）。
- 展柜 / 相册的落盘文件名由程序按槽位 id 生成，不含用户输入路径；扩展名白名单 + 大小上限。
- 自由摆位只接受 `x 5–95 / y 18–98` 的有限数，系列名只接受 ≤ 8 个字符的字符串，主进程再夹一次，渲染进程传什么都越不了界。
- 验证一律用 `XOME_TEST_DESKTOP` / `XOME_TEST_DATA` / `XOME_TEST_NO_PIN` 指向临时沙箱。

## 4. 各模块的特色与作用

> 每模块固定四栏：职责 / 特色 / 关键实现 / 可证伪判据。

### 4.1 M1 桌面层窗口与命中穿透

- **职责**：把星球钉在壁纸之上、应用之下，并决定鼠标事件交给谁。
- **特色**：窗口 `focusable:false`；按住 Alt 时由 `mousemove` 自带的 `altKey` 临时接管整层，松开自动恢复。
- **关键实现**：`workArea` 而非 `bounds`；`win32.pinAboveDesktop` + 800ms 重锚；缩放用 `clientWidth/clientHeight` 并监听三种尺寸变化。
- **判据**：`#app` 的 `transform` 矩阵与 `app.getBoundingClientRect()` 一致，且不超出视口；底部留白 ≥ 24px；1600×1000 下画布 1504、柜体 1452、中列 542；1920×1080 下画布展开到 1671、中列 709、柜体 1619、画面宽 1863；3120×2080 下画布 3101×2024、底部留白 56；在 2560×1440 视口选 1080p 档，画面块正好 1920×1080，选自动档画布高 1397、底部留白 43；空白穿透、命中区接管。

### 4.2 M2 桌面文件桥

- **职责**：把真实桌面变成渲染进程可用的数据。
- **特色**：所有桌面项统一进 `files`，图片不单独分流；系统真实图标；`.lnk` 先解析目标程序再取图标。
- **关键实现**：`SKIP` 过滤系统文件；`app.getFileIcon` 取 large 图标；`pathToFileURL` 统一编码中文 / 空格 / `#`。
- **判据**：10 个桌面项 → 地毯 10 张卡，10 张都有 `<img>` 系统图标。

### 4.3 M3 收纳引擎（复用）

- **职责**：文件真移动、还原、排序、日志、对账。
- **特色**：纯 Node、可单测；撞名不覆盖；`move()` 只改元数据不动文件；文件夹记录子项数；`discard()` 让「原件已进回收站」的条目同步消失。
- **关键实现**：`shelf.json` + `journal.jsonl`（intent/done 成对）+ `shelf\` 原件目录。
- **判据**：`node room/test-store.js` → 42/42；重新 `new Store()` 读盘后层号与顺序不变；文件夹条目 `count` 等于可见子项数。

### 4.4 M4 地毯资料层

- **职责**：未收纳文件以带糖果感的卡片散落在地毯上。
- **特色**：卡片里是**系统给的原图**（不重绘图标），外面套一张奶油色小卡与彩色类型标签；歪斜 ±8°；新文件掉落动画。
- **关键实现**：`poseOf()` 按文件名把落点写进 `layout.json`；`freshPose()` 用网格 + 横向错位保证不重叠；`--dx/--dy` 拖拽不改布局；点选模式点一下切换选择。
- **判据**：卡片数 === 桌面文件数；歪斜角全在 ±8° 内；点一下选中 1 张；批量上架后书架 +1、地毯 −1、选择清空。

### 4.5 M5 五层糖果书架

- **职责**：收纳后的呈现与再组织。
- **特色**：五层、每层一条糖果色层板；资料类按扩展名配色并**竖排写书名**——所有书脊统一 66px 高（以效果图里「春夏秋冬备忘」那本为基准）、固定写六个整字前缀、第一个字一律从顶部 10px 起笔，不同格式（含 `2026年度计划.xlsx` 这种数字混排）完全齐平；**普通文件夹与文件夹快捷方式也统一为资料同款竖排四字书脊**，不再有正面 2×2 标签和子项数量角标——普通文件夹保留暖牛皮色、快捷方式保留蓝灰 + 右上折角，只靠配色区分类型（设计取舍见附录 N，统一高度见附录 O）。
- **关键实现**：`renderShelf` 按 `row/order` 分组排序；容量用真实 `clientWidth` 估算，放不下直接拒绝并提示；`SPINE_H = 66` / `docHeight()` 对资料、文件夹、快捷方式一视同仁；`PM.spineChars(66)` = 6，`PM.shortName` 只截整字；`text-orientation:upright` 让数字/英文与汉字等高步进，`.spine-name` 用 `margin-top:10px` 顶对齐 + `padding-bottom:2px` + `max-height:calc(100% - 11px)`，保证六字不裁、起笔一致（用 margin 而非 padding-top，因为全局 `box-sizing:border-box` 下顶 padding 会挤掉可排字数）；桌面房间同规则（书高统一 0.88 行高、资料同样截六字整字，不再靠 CSS 硬裁长名）。
- **判据**：`node room/test-store.js` 的排序断言 + 验证里「拖到第 5 层后层级为 4」「拖出后地毯 +1 / 书架 −1」；本轮新增 4 条断言：8 种格式资料书脊全为 66px、第一个字起笔最大差 0.00px、同层顶边齐平、upright 且 `overflow 0`；`海边照片收藏 → 海边照片` 竖排四字、无 `.box-label` / `.box-count`、24×66、`Range` 量第四字完整可见；快捷方式书脊 `资料快捷` 四字、无角标；两类书脊背景色不同。房间主题另新增六字整字前缀与起笔一致性断言（87/87）。

### 4.6 M6 甜甜相册

- **职责**：玩家自定义 4 张拍立得。
- **特色**：麻绳夹着、轻微钟摆；选图后有显影动画；**存快照，不存原路径**。
- **关键实现**：`nativeImage` 缩到 1200px / JPEG 82（只缩不放）；PNG/JPEG 走重编码，gif/webp/avif/bmp 存原字节；`frames.json` 按格 id `p1..p4` 存；URL 由 `pathToFileURL` 生成。
- **判据**：**把原图收进书架后相册仍显示**（引用方案必失败、快照方案必通过的分水岭）；`frames/p1.jpg` 真的存在；清空后回到斜纹占位。

### 4.7 M7 今日小愿望

- **职责**：待办便签。
- **特色**：**没有勾选框与完成态**——做完了点 × 撕掉，toast 提供撤销；拖进糖果罐会先归档成 Markdown 再删除。
- **关键实现**：双列网格、`white-space:pre-wrap`、便签内滚动、固定高度；`layout.json` 持久化；撤销用 `removeAt/insertAt` 插回原位置。
- **判据**：`.chk` 数量 0；删除后 5→4 且出现撤销；撤销后 4→5；新增多行后 6 条且 `layout.json` 落盘。

### 4.8 M8 糖绒展柜

- **职责**：让玩偶「真的站在玻璃柜里」，并让形象可自定义、可持久化。
- **特色**：连续玻璃舞台（背板纵深 / 锥形射灯 / 椭圆地台 / 接触阴影 / 前后高低错位）；四套系列只换灯光与站位；形象存成**文件**，支持 PNG 与 GIF（不转码）；**玩偶可自由拖动摆放**，松手记住位置，按脚底线重算景深；系列标签可双击改名。
- **关键实现**：`model.js` 的 `STAGES[1..6]` 站位表（x/y 百分比、s 缩放、z 层级、rot 旋转、b 亮度、blur 景深）+ `clampPose()` + `poseScale()`；`showcase.json` 存 `poses`（每格 `{x,y}` 或 null）与 `labels`（系列自定义名）；`figures/sN.ext` 存图片；`?v=mtime` 破缓存；切系列只改 `series/count`，`files` / `poses` / `labels` 不缩短。
- **判据**：5 只时缩放与层级各至少 4 种不同值；PNG 上传后出现 `/figures/s0.png` 的 `<img>`；GIF 源是 `.gif`；JPG 被拒绝；加到 6 后不再增加；切焦糖 = 3 只且 2 张图仍在；把第 1 只拖到左下后 `poses[0]` 落盘、`--s 0.82→0.93`、`--z 3→7`；点「重排」后 `poses` 全 null、`--x` 回到 20%；双击标签改名后标签、铭牌、`showcase.json.labels` 三处一致，能恢复默认。

### 4.9 M9 糖霜唱片机

- **职责**：本地 MP3 简易播放器。
- **特色**：三态全实现；模式按钮固定短标签「模式」，当前状态只放 tooltip（副标题已去掉）；右侧按「标题 / 按钮 / 状态+进度」三段纵向撑满；没选 MP3 时播放一段演示旋律，唱片真转。
- **关键实现**：`room/player-state.js` 一份状态机；`xome-planet-audio` 协议只放行已选目录的 `.mp3`；`<audio>` 负责真实播放，`OscillatorNode` 负责演示旋律（用户点击后才创建 AudioContext）。
- **判据**：三态按钮循环 → tooltip 依次「播完即停 / 单曲循环 / 列表循环」且 `audio.json` 写回 `all`；演示态 `#disc.spin` 为真、按钮变「暂停」，再点停止。

### 4.10 M10 我的电脑

- **职责**：左上入口与状态屏。
- **特色**：**140×140 正方形**屏，9px 奶油机身包住 **122×122 暖梅色玻璃**；磁盘 / 内存是**真实读数**（概念稿的 68/42 是模拟值）；6 个快捷入口真的打开系统位置；双击进屏保。屏下不再挂常驻操作提示，操作说明只在帮助抽屉里出现。
- **关键实现**：`fs.statfsSync(SystemDrive)` 算磁盘占用，`os.totalmem/freemem` 算内存；取不到返回 `null`，界面显示「—」；`pc:open` 白名单映射到 `app.getPath(...)` 与回收站；每 30 秒刷新。
- **判据**：屏宽 === 屏高 === 140；磁盘/内存文本匹配 `数字%` 或「—」；点一下弹 6 个入口；双击后 `.saver` 生效且状态信息隐藏；页面里不存在 `.pc__hint`。

### 4.11 M11 糖果罐

- **职责**：删除与归档。
- **特色**：文件、书脊、便签都能拖进来；文件和书脊走**系统回收站**（可恢复），便签先在 `notes-archive.md` 留一份文本再删除。
- **关键实现**：`shell.trashItem`；书脊删除成功后 `store.discard` 同步移除条目；便签拖拽用指针位移判定落点。
- **判据**：便签归档后 `notes-archive.md` 含原文；书脊条目在丢弃后不再出现在 `shelf.json`。

### 4.12 M12 收纳记录与说明

- **职责**：可追溯与交接说明。
- **特色**：日志面板只显示最近 14 条，可一键还原全部、打开收纳目录、打开便签归档；说明抽屉写清功能映射、数据位置与版权边界。
- **关键实现**：`journalTail(60)`；`restoreAll()` 逐条失败不中断；说明为静态 HTML，不依赖脚本。
- **判据**：打开后 `.journal__row` 数量 > 0；抽屉 `.on` 生效；Esc 与点击外部可关。

### 4.13 M13 氛围与可访问性

- **职责**：让「我做了一件事」有回响，并保证基础包容性。
- **特色**：常驻动效（呼吸 / 钟摆 / 星尘 / 云漂）低幅度；Q 弹、撒星、toast 只在操作反馈出现；`:focus-visible` 焦点环；`prefers-reduced-motion` 一刀切关动画。
- **判据**：CSS 中存在 `focus-visible` 与 `prefers-reduced-motion`；展位有 `aria-label`、可 Tab 聚焦。

### 4.13b M15 底部应用坞

- **职责**：把桌面上的应用快捷方式固定收在柜体底部，提供 2/3 条**无名称的自由摆位槽**，不占地毯；用户想把哪个应用放哪一栏都行。
- **特色**：`.lnk` / `.url` / `.exe`（且不是文件夹快捷方式）自动入坞；`img` 直接渲染系统原图标，不做着色；2 栏 / 3 栏切换；**分组不显示任何栏名**（第十七轮移除「工作 / 工具 / 娱乐」「常用 / 其他」），只留虚线分隔；拖动图标可在栏内换位或跨栏，右键菜单用中性的「移到第 N 栏」；空槽显示「拖到这里」。
- **关键实现**：`listDesktop` 为 `.lnk/.url` 补 `linkDir`；渲染层 `isAppShortcut` 过滤，应用从地毯移入坞；`model.js` 的 `reconcileDock` 保留旧摆位、新应用放进最空组（纯容量均衡，不按类型），`moveDockItem` 处理跨栏插入，`setDockCols` 切栏时把多余组并入最后一栏；`layout.json.dock = {cols,items:[{key,g,o}]}`，数据里本来就没有分类字段。
- **判据**：3 个应用入坞、地毯仍是 `docs.length + 4`；默认 3 栏；**DOM 无 `.dock__label`、坞内不含任何分类词**；右键 3 项全是「移到第 N 栏」；切 2 栏后条目仍 3、组号 ≤1、`layout.json.dock.cols === 2`；拖动后目标条目 `g === 1` 且落盘；切回 3 栏仍是 3 个图标。

### 4.14 M14 验证体系

- **职责**：保证每次改动没破回归。
- **特色**：沙箱隔离 + 真 Electron + CDP 注入断言；断言里**真的**把临时文件收进书架、拖出来、上传真 PNG/GIF、切系列、删便签撤销。
- **关键实现**：系统分配空闲端口；`Emulation.setDeviceMetricsOverride` 依次切 1600×1000 / 1920×1080 / 2560×1440 / 3120×2080；结果写 `verify/logs/planet-验证结果.json`，截图写 `docs/planet-theme.png`（初始）与 `docs/planet-theme-1920.png`（16:9 成品）；另有打包版冒烟脚本。
- **判据**：`72/72`、`pageErrors: []`、截图可打开、打包版冒烟 2/2（普通 + `--tray` 检查托盘菜单与桌面层锚定）。

## 6. 已知问题或风险

### 6.1 技术风险

| 风险 | 表现 | 缓解 |
|---|---|---|
| 页面缩放导致柜体溢出 | `window.innerHeight` 比真实布局视口大 2% | 用 `clientWidth/clientHeight` + `ResizeObserver`（本次已修） |
| Win+D 抖动 | 「显示桌面」时输入法窗口插入 Progman 之上，星球被顶出一瞬 | 800ms 重锚拉回；不影响使用 |
| 键盘事件缺失 | `focusable:false` 收不到 keydown | 修饰键用鼠标事件 `altKey`；弹编辑器时临时 `setFocusable(true)` |
| `file://` 编码 | 手工拼 URL 会让中文 / 空格 / `#` 断图 | 一律 `pathToFileURL`；展柜与相册用程序生成的文件名，URL 不含原始文件名 |
| 路径穿越 | 渲染进程传路径给主进程 | `insideKnown` + 扩展名白名单 + 协议层前缀校验 |
| 书架容量估算偏差 | 书脊宽度按类型固定 22/24px（资料/文件夹与快捷方式，附录 N 后统一） | 估算偏保守；放不下会明确拒绝，不静默丢文件 |

### 6.2 数据与文件安全风险

- 收纳是**真移动**，`shelf\` 被删就等于用户文件丢失。任何清理脚本都不得递归删除该目录。
- `layout.json` 高频写，原子替换不可省；低频配置必须独立文件。
- 验证脚本若未设置沙箱环境变量，会操作真实桌面 —— 跑之前先确认 env。
- 书脊拖进回收站后，`discard` 会移除条目；文件仍在回收站里，可手工恢复，但应用内不再显示。

### 6.3 素材与合规

- 界面与内置形象均为本项目矢量绘制；外部图片由使用者自行上传。
- 对外分发时，请确认所使用素材的授权。

### 6.4 平台与环境风险

- 仅覆盖 Windows 10/11 主屏；`win32.js` 缺失时降级为「只创建窗口、不钉层级」。
- 高 DPI 下 CSS 尺寸按设备无关单位算，别写死像素。
- 托盘图标在 Win11 默认收进 `^` 溢出区，首次要拖出来；`退出糖绒星球.bat` 是兜底。
- `fs.statfsSync` 在极少数文件系统上会抛错，界面降级为「—」，不会编假数字。

## 7. 开发者的编码风格与偏好约定

> 本章与 01 / 02 的 §7 **逐条相同**，不重复粘贴以免三处漂移。下面只记本主题线新增的落地做法。

- **复用优先于复制**：共用模块只有一份（`room/store.js`、`room/player-state.js`、`room/win32.js`），`planet/` 通过相对路径 require。打包时由 `tools/pack-planet.mjs` 把这三个文件一起带进 `build/planet-stage`。
- **纯逻辑抽出去**：站位、槽位增删、地毯排布、画布换算全部在 `planet/model.js`，不埋在 DOM 事件里；`test-model.js` 直接 require。
- **配置与产物分离**：`showcase.json` 只存文件名与元数据，图片在 `figures\`；`frames.json` 同理。不要把 dataURL / 二进制塞进 JSON。
- **设计 token 只在一处**：颜色、圆角、阴影全在 `:root`；系列色通过 `--sc-a/--sc-b/--sc-lamp` 由 JS 注入。
- **判定规则写法**：仍然「只有 X 算，其余一律不算」；容量类枚举必须注明「代码限制」。
- **验证同步**：行为变化必须同步改断言数字；新增能力至少补一条可证伪断言。01 侧的 86 条与 03 侧的 75 条断言都在结果 JSON 里可查；新增能力至少补一条可证伪断言。

## 附录 O. 不同格式资料的书脊起笔统一（2026-11-22，第十四轮）

> 用户反馈：「不同格式的资料，在书架上显示的文字的初始高度不一致，能够都按照效果图中『春夏秋冬备忘』这个高度来调整。」

### O.1 根因：三件事叠在一起

| 原因 | 后果 |
|---|---|
| `docHeight(name) = 54 + hash(name) % 18` | 书脊高度按文件名在 54–71px 抖动，底边都贴层板时**顶边本来就不齐** |
| `.book` 是 `align-items:flex-end` | 竖排文字按自身高度贴着书脊底边，字数少的书第一个字**往下掉** |
| `text-orientation:mixed` | `2026` 这类数字横躺，四个数字只占约 20px（汉字四字约 35px），文字块被压短，起笔又低一截 |

效果图里四本分别是 66 / 69 / 68 / 58px、6 / 6 / 6 / 5 字，绿色那本「2026年度」起笔明显偏低，就是这三条叠加的结果。

### O.2 改动：以「春夏秋冬备忘」那本为唯一基准

| 项 | 之前 | 现在 |
|---|---|---|
| 书脊高度 | 资料 54–71px（哈希）、文件夹 58px | **全部 66px**（`SPINE_H` / `docHeight()`）；房间主题统一 0.88 行高 |
| 文字对齐 | 底对齐（`flex-end`） | **顶对齐 + `margin-top:10px`**，所有格式第一个字同一起笔 |
| 字符步进 | `mixed`，数字横躺 | **`upright`**，数字/英文与汉字都按 8.8px/字 |
| 显示字数 | 按书高 4–6 字 | **统一六个整字前缀**（短名按实际字数），全名走悬停提示 |
| 文字框 | `max-height:calc(100% - 8px)` + `padding-bottom:3px` | `margin-top:10px` + `padding-bottom:2px` + `max-height:calc(100% - 11px)`；六字 ≈ 52.8px 落在 53px 内，`overflow 0` |
| 房间主题长名 | 显示完整文件名，被 CSS 硬裁成半截字 | 与星球一致截六字整字，不再有半截字 |

**为什么用 margin 而不是 padding-top**：全局 `*{box-sizing:border-box}`，`padding-top` 会被算进 `max-height`，实测 `overflow=10`（六字被裁成不足五字）；改用 `margin-top` 后 `overflow=0`。**为什么保留 2px 底 padding**：给文字框留呼吸，也让「第四字完整可见」的 `Range` 判据有 1px 以上余量。

设计取舍：所有书等高会让书架失去原本「高矮错落」的手作感，但用户明确要求格式之间一致，且并排时顶边不齐比错落更显乱；因此**连文件夹与快捷方式也一并统一到 66px**，整层书脊顶边、起笔完全齐平。颜色仍是唯一的类型区分（资料多色 / 文件夹暖金 / 快捷方式蓝灰折角）。

## 附录 Q. 左上角绿植与电脑台面对齐（2026-11-22）

> 用户诉求（第十四轮提出、当时因限额未执行）：「左上角植物摆放得偏低，需要向上移动，使其底部与电脑显示器和主机箱的底边保持水平对齐」。

### Q.1 根因

概念稿 `docs/theme-preview.html` 里三件物品本来落在同一条台面：屏幕 `top:18 + height:140 = 158`、机箱 `18 + 140 = 158`、绿植 `top:72 + height:88 = 160`（差 2px，肉眼齐平）。产品版把屏幕与机箱上移到 `top:4`（底边 144px），绿植却改成了 `bottom:16px` 相对 `#zonePC`（高 184px）定位 → 盒底 168px，**比台面低了 24px**，于是左上整组看起来「绿植往下掉」。

### Q.2 改法（`planet/planet.css` 一行）

```css
/* 之前 */ .pc__plant{right:10px;bottom:16px;width:78px;height:88px}
/* 现在 */ .pc__plant{right:10px;top:60px;        width:78px;height:88px}
```

- 改用 `top` 而不是继续调 `bottom`：`#zonePC` 高度将来若变化，`bottom` 会把绿植重新带偏，而 `top` 锁的是与屏幕同一个坐标系。
- 盒底取 **148px** 而不是 144px：`PLANT_SVG` 的 `viewBox="0 0 62 70"`，花盆只画到 y≈67（描边外缘 ≈67.25），容器底部还有约 3–5px 透明留白。盒子再往下 4px，花盆的**视觉**底边才正好落在 144px 台面上。
- 尺寸 78×88、`right:10px`、`drop-shadow` 全部不变；绿植仍在 `#zonePC` 内（顶 60px、盒底 148 < 184），与机箱右边缘保持 12px 间隙。

### Q.3 判据（`verify/verify-planet.mjs` 新增 3 条）

用 `offsetTop/offsetHeight` 而非 `getBoundingClientRect`：舞台整体有 `transform:scale()`，布局值不随档位漂移；花盆视觉底边由 SVG `getBBox()` 与 `viewBox` 反推下方留白。

| 断言 | 实测 |
|---|---|
| 显示器与主机箱底边在同一水平线 | 144 / 144 |
| 绿植上移后花盆底边与两者齐平 | 台面 144 / 花盆视觉底 143.0（差 1px）/ 盒底 148 / 顶 60 |
| 绿植仍在电脑区内且不与机箱重叠 | 左 264 / 机箱右 252 / 区高 184，通过 |

> 视觉证据：`docs/planet-pc-screen.png`（`verify-planet.mjs` 用 CDP `clip` 输出的「我的电脑」3× 特写）、`docs/planet-theme-1920.png`（整屏 16:9）。房间主题没有这块「我的电脑」部件，本轮未改动。基线：单测 115/115、星球端到端 116/116、房间端到端 87/87、打包冒烟 2/2。

## 附录 S. 书脊文字统一深墨粗字（2026-11-22，第十八轮）

> 用户诉求：「你看，书架上的字体，明显右边这个显示的文字更醒目」。截图里文件夹 / 快捷方式的竖排四字是深墨粗字，资料书脊却是中饱和彩底 + 白色细字，两类并排时资料那几本明显发虚。

### S.1 问题

第十四轮统一了书脊**几何**（66px 同高、顶部 10px 起笔、`upright` 整字前缀），但没有统一**文字色与字重**，于是并排看仍是两套视觉语言：

| 类型 | 第十八轮之前 | 观感 |
|---|---|---|
| 资料（`.book.doc`） | 中饱和格式色作中段底 + `rgba(255,255,255,.97)` 白细字（默认 400）+ 暗色投影 | 浅粉 / 浅蓝格式上白字几乎融进底色，深色格式上又发灰 |
| 普通文件夹（`.book.box`） | 暖牛皮浅底 + `#5E4327` 深墨字（600）+ 白色高光 | 清楚、醒目 |
| 文件夹快捷方式（`.book.box.link`） | 蓝灰浅底 + `#233F5D` 深墨字（600）+ 白色高光 | 清楚、醒目 |

**为什么不能只把资料字改深**：PDF `#C43E1C`、PPT `#E79A7D`、房间主题的 Office 深蓝 `#2F5597` 这类格式色本身就暗，深墨字写上去会糊成一团，必须先把**底**抬亮。**为什么不能全刷成同一个浅色**：按格式配色（Word 蓝 / Excel 绿 / PPT 橙红 / PDF 红 / 文本灰蓝 / 图片紫 / 压缩包棕）是要保留的类型辨识，全刷白就把这个信息丢了。

### S.2 改法

| 位置 | 之前 | 现在 |
|---|---|---|
| `planet/model.js` | — | 新增 `lightenInk(hex, ratio = INK_MIX)` 与常量 `INK_MIX = 0.6`，导出到 `PM` |
| `planet/planet.js` `renderShelf()` | 资料只写 `--ink` / `--ink-dark` | 追加 `b.style.setProperty('--ink-light', PM.lightenInk(ink[0]))` |
| `planet/planet.css` `.book.doc` | 中段 `var(--ink)`、两侧 `var(--ink-dark)` | 中段 `var(--ink-light)`（22%–78%），**两侧立边改回原格式色 `var(--ink)`** |
| `planet/planet.css` `.book .spine-name` | 白字 400 + `text-shadow:0 1px 1px rgba(90,50,70,.35)` | `#2A3A52` / **700** + 白色高光 `0 1px 0 rgba(255,255,255,.72)` |

`lightenInk` 的规则：每通道按 `c + (255 - c) × 0.6` 混白，**保留色相、只抬亮度**；支持 `#rgb` / `#rrggbb` / 不带 `#`，非法值回落中性浅色，`ratio` 夹在 0..1（0 = 原色、1 = 纯白）。放进 `model.js` 是为了能纯逻辑单测；房间主题的 `room.js` 不加载 `model.js`，故内联同一份规则，两处注释互相指名。

**不动的东西**：66px 书高、顶部 10px 起笔、`upright` 六字整字前缀、文件夹 / 快捷方式竖排四字、应用坞、舞台坐标、第十七轮去掉的栏名、第十五轮的整圈外框——**这轮只动颜色与字重，不动任何几何**，所以此前所有布局 / 对齐 / 起笔断言原样通过。`--ink`（原格式色）只是从「中段」挪到「两侧立边」，仍参与配色辨识。

### V.8 桌面应用快捷方式「原图标」提取整改（2026-11-22）

现象：应用坞里有少数快捷方式只显示通用空白文档图标，不是应用原图标。

根因（从 app 侧定位，不改源快捷方式）：
1. 旧实现把 `.lnk` 的 `IconLocation`（如 `app.exe,-101`、`icon.dll,5`）里的**索引直接丢弃**，再用 `app.getFileIcon` 取 0 号图标；索引不为 0 时就取到空白/错误图标。这是企业类应用（金蝶 EAS 等）常见的失败原因。
2. Electron `app.getFileIcon` 只给 **32×32**，高分屏下偏糊。
3. `.url` 只读了 `IconFile`、没读 `IconIndex`。

修法（新增 `planet/assets/icon-extract.ps1`，由 `main.js` 批量调用）：
- 用 Win32 `PrivateExtractIconsW` 按 **索引** 提取图标，逐级尝试 **256 → 128 → 64 → 48 → 32 → 16**，取最大可用图标；索引支持负数（资源 ID）。
- `shortcutIconSpec()` 解析 `.lnk` 的 `IconLocation`（文件+索引）与 `.url` 的 `IconFile`+`IconIndex`。
- `psIconSource()`：有显式图标按索引取；否则取 `.lnk` 目标 exe 的 0 号图标（排除 UWP 的 `explorer.exe` 目标）。
- `psExtractIcons()` 批量一次 PowerShell 调用，返回 dataURL；base64 长度 ≤ 700 视为空白图标，回退到 `iconFallback()`（原 `getFileIcon` 候选链，32px）。
- 结果按路径缓存，刷新只对新增文件重算。

实测（本机真实桌面 9 个快捷方式）：8 个升级为 256px 高清图标（dataURL 4–50KB），仅 `录制.lnk`（目标是非 exe 的数据文件，本身无图标资源）走通用兜底。

### V.9 系列切换导致图片「部分不显示」整改（2026-11-22）

### V.10 倾斜按钮误弹添加图片窗 + 静态图识别（2026-11-22）

### V.11 隐藏→显示后整个星球点不动（根治）（2026-11-22）

上一轮加的 `planet:resync` 治标不治本。真正的根因：**`win.hide()` + `win.showInactive()` 会破坏 `setIgnoreMouseEvents(true,{forward:true})` 的鼠标转发**（Electron 在 Windows 上的已知问题）。显示后渲染进程再也收不到 `mousemove`，`lastPointer` 停在旧位置，于是永远停在穿透态——添加图片、拖动、扔回收站全部点不动。

修法：**不再真正隐藏窗口**。
